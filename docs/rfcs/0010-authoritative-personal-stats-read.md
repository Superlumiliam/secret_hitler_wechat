# RFC-0010：个人战绩权威读取

## 目标

个人资料页从服务端读取当前用户的最新多人战绩，避免异步统计已写入数据库但本地资料缓存仍长期显示 `0`。

## 背景与证据

多人战绩由维护链路异步写入 `user_profiles`，但资料页只读取微信本地缓存，应用启动和页面恢复也不会同步统计字段。因此数据库与页面会永久分叉。

## 方案

- `bootstrapService` 新增只读 action `getPersonalStats`，按云函数上下文中的 openid 读取当前资料。
- 只返回五个非负整数统计字段；资料缺失或旧字段缺失时按 `0` 返回。
- 资料页每次显示时刷新服务端战绩；用户名和头像继续使用本地缓存。
- 资料编辑保存不再复制统计字段，客户端不能提交或覆盖权威战绩。

## 边界

- 包含：当前用户战绩读取、页面刷新、只读边界和自动化测试。
- 不包含：排行榜、他人战绩、逐局记录、历史补偿或统计事件可靠性改造。
- 必须保持的不变量：统计只由服务端终局消费链路更新；客户端身份来自云函数上下文。

## 接口与兼容性

新增 `bootstrapService.getPersonalStats`，payload 为 `{}`，返回 `PersonalStats`。旧客户端不调用该 action，不受影响；没有新增枚举或错误码。

## 失败场景与安全

读取失败沿现有统一协议返回可重试的 `INTERNAL_ERROR`，页面保留当前显示并记录错误。action 只读取当前 openid 对应资料，不接受目标用户标识，也不返回 openid。

## 验收

- [x] 数据库统计非零时，资料页显示服务端最新值和正确胜率。
- [x] 资料缺失或旧统计字段缺失时返回五个 `0`。
- [x] 编辑用户名或头像不会提交、复制或覆盖统计字段。
- [x] 后端 action 与资料页刷新有自动化测试，相关回归测试通过。
- [x] 同步更新产品、API 和架构文档；无需微信开发者工具之外的环境迁移。

## 决策

方案于 2026-08-06 接受并实现。属于窄范围只读 DTO，不需要 ADR。
