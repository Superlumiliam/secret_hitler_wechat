# RFC-0008：多人统计异步事件

## 目标

把个人统计累计从游戏终局事务中移出，避免资料读取或统计写入失败阻塞游戏结束和结果页，同时保持同一对局最多累计一次。

## 背景与证据

RFC-0007 将所有真实玩家资料读取、统计更新和终局状态放在同一事务中。任一资料操作异常都会回滚合法终局，扩大了统计故障的影响范围。现有终局路径都经过 `persistEndedRoomProjection()`，维护函数已有定时触发、集合初始化和有限并发基础。

## 方案

- 新增 `multiplayer_stat_events`，以 `gameId` 作为文档 ID。普通多人终局事务只写一条 `pending` 事件，事件冻结真实玩家的 `memberId`、`openId` 和胜负；不包含观战者、虚拟席位或单人对局。
- `maintenanceService` 每次最多读取 100 条待处理事件并有限并发消费。单条消费事务读取事件和资料、累计所有存在资料的统计，并在同一事务内删除事件。
- 消费事务失败时回滚全部统计写入，再用独立事务递增 `failureCount`。首次失败后重试两次，第三次仍失败则删除事件并记录脱敏诊断。
- 整份资料缺失时跳过该玩家并记录诊断，不把缺失视为事件处理失败。统计字段缺失按 `0` 计算。

## 边界

- 包含：终局事件、异步累计、原子删除、三次失败删除、集合初始化、并发和失败测试。
- 不包含：前端统计展示、逐局永久档案、排行榜、人工补偿 action 或历史战绩追溯。
- 必须保持的不变量：`multiplayerGameCount = multiplayerWinCount + multiplayerLossCount`；同一事件最多成功累计一次；待处理事件不随房间清理删除。

## 接口与兼容性

无客户端 action、DTO、枚举或错误码变化。默认维护结果新增 `multiplayerStatEventResult`，包含 `scanned`、`processed`、`retryScheduled` 和 `dropped` 计数，不返回玩家标识。

## 失败场景与安全

事件入队与终局状态原子提交；成功入队后的统计故障不再影响结果链路。事件消费以事务内重新读取为准，并发维护只允许一个事务更新统计并删除事件。失败计数事务若发现事件已被其他消费者删除则不再处理。批次查询失败或单条失败不阻塞房间与幂等记录清理。事件仅服务端可见，日志不记录 openid。

## 验收

- [x] 正常多人终局只写一条 `gameId` 事件，不读取或直接更新个人统计。
- [x] 成功累计与事件删除同事务提交，删除失败时统计更新回滚。
- [x] 失败次数按 `0 → 1 → 2 → 删除` 演进。
- [x] 缺失资料跳过；单人、观战者、虚拟席位和未终局对局不累计。
- [x] 并发消费最多累计一次，单条失败不阻塞同批其他事件。
- [x] 自动化测试和当前架构、API、路线图已同步。

## 决策

方案于 2026-08-02 批准并实现，取代 RFC-0007 中“终局事务直接累计个人统计”的部分，不需要 ADR。上线必须先部署并触发维护集合初始化，再部署写入事件的游戏函数。
