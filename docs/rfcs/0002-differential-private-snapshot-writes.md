# RFC-0002：差异化私密快照写入

## 目标

减少游戏命令对未发生私密状态变化席位的数据库写入，同时保持公共同步即时性、版本并发校验和私密信息隔离。

## 背景与证据

`gameService` 当前为每条游戏命令生成并写入全部成员私有快照。投票阶段每次投票都会递增全局 `gameCore.version`，导致未投票玩家的任务 ID 变化并触发无意义写入。架构要求私有投影按席位生成，路线图将差异化私密快照更新列为工程优化候选。

## 方案

- 任务 ID 统一为 `gameId:round:phase:taskType:memberId`，不包含全局 `version`；`expectedVersion` 继续独立校验陈旧命令。
- 命令事务使用迁移前后的 `game_core` 在内存中生成私有投影，忽略投影时间戳后比较身份、投票、手牌、调查结果、政策预览、待办任务和终局元数据。
- 只更新变化席位；公共快照、同步信号、核心状态和公开事件仍按原流程更新。终局状态或结果过期时间变化时更新全部席位。
- 不读取私有快照进行比较，不把任何私密字段移动到公共投影。

## 边界

- 包含：所有游戏命令分支的私有快照差异写入、稳定任务 ID和相关文档测试。
- 不包含：新 action、字段、集合、前端任务解析或缺失私有文档修复。
- 必须保持：公共版本即时递增；客户端以公共快照版本为准；身份、手牌、未公开投票和任务不泄露。

## 接口与兼容性

无新增 action、字段、枚举或错误码。`taskId` 的生成格式发生变化；旧的包含 `version` 的格式严格拒绝，客户端必须刷新快照获取新值。投票仍允许不携带 `taskId`，`expectedVersion` 规则不变。

## 失败场景与安全

版本冲突、阶段校验、操作者校验、幂等和目标校验保持不变。差异比较只使用服务端真相 `game_core`，不会信任客户端数据，也不会增加私密快照读取。终局状态变化必须覆盖全部私有文档，避免席位保留活跃状态。

## 验收

- [x] 任务 ID 不随同阶段和轮次内的 `version` 变化，并区分阶段、轮次、任务类型和玩家。
- [x] 10 人投票中中间命令只写入投票玩家，最后一票正确更新阶段变化席位。
- [x] 命令处理不增加 `player_private_snapshots` 读取。
- [x] 旧任务 ID 被拒绝，现有规则、隐私和终局测试通过。

## 决策

实现完成于 2026-07-27；该优化不引入需要 ADR 的长期技术取舍。
