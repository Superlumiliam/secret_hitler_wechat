# RFC-0003：三席观战模式

## 目标

为普通多人和单人房间固定提供 3 个观战席，让领队可以不占玩家名额地教授对局，并允许对局开始后通过邀请链接或房间码加入公共观战视图。

## 背景与证据

当前 `room_members` 的有效成员会被直接用于开局人数、角色分配、投票、私密快照和终局结果。若只扩大厅席位，观战者会被错误计入规则人数并获得私密信息，因此必须显式区分房间成员和游戏玩家。

## 方案

- `room_members.memberType` 使用 `player`、`spectator`；历史记录缺失时按 `player` 处理。
- 玩家席和观战席分别编号，观战容量固定为 3；大厅加入优先玩家席，玩家满后进入观战席。
- 房主身份与席位类型解耦；准备、角色、游戏命令和私密投影只属于玩家。
- 开局后玩家名单冻结，新成员只能进入空观战席；观战快照只包含公共投影。
- 单人观战房主默认使用公共视图，但可继续显式操控归属于自己的虚拟玩家。

## 边界

- 包含：大厅观战 UI、跨类型换席、局内观战加入、恢复、同步、结果访问和单人模式虚拟操控。
- 不包含：动态观战容量、房主移除观战者、自动断线回收、局内玩家替补或观战私有视图权限开关。
- 必须保持：标准规则只计算 5–10 名玩家；普通观战者不能获得身份、手牌、调查结果、政策预览、待办或命令权限。

## 接口与兼容性

- `claimLobbySeat` 增加可选 `targetMemberType`，缺省为 `player`。
- `joinRoom` 支持对局中加入观战，响应增加 `memberType` 和 `routeHint`。
- `LobbyView` 增加固定观战容量、观战人数、观战席列表和当前成员类型。
- `GameSnapshot` 增加真实成员类型、是否观战视图和是否拥有私密视图。
- 新增 `SPECTATOR_SEATS_FULL`；不增加集合、API 版本或未来权限预留字段。

## 失败场景与安全

入席和换席在事务中校验类型内唯一性。对局中离线玩家重新加入时恢复原玩家记录，新用户只能创建观战记录。主动离开的观战者释放席位，退后台或断网仍保留以便恢复。局内成员变化不得用房间大厅版本覆盖当前游戏同步版本。

## 验收

- [x] 普通与单人大厅均显示 3 个观战席，跨类型双击换席符合准备规则。
- [x] 10 名玩家和 3 名观战者仍只创建 10 份身份与私密快照。
- [x] 普通观战者只能读取公共快照且不能提交命令。
- [x] 单人观战房主可在公共视图与受控虚拟玩家之间切换。
- [x] 局内邀请、恢复、主动离开、结果复盘和现有自动化回归测试通过。
- [ ] 微信开发者工具和目标云环境验证同步信号只读权限。

## 决策

方案已于 2026-07-27 实现并同步当前权威文档；无需 ADR。发布前仍需完成微信开发者工具冒烟和目标云环境安全规则确认。
