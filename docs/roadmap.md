# 《secret dictator》1→100 路线图

## 使用方式

MVP 功能闭环已经完成。本页只记录候选需求和工程改进，不代表已承诺范围或现行契约。

状态定义：

- `candidate`：有价值但尚未排期。
- `discovery`：正在补充目标、证据和方案。
- `planned`：已批准并有可实施 RFC 或明确验收标准。
- `in-progress`：正在实现。
- `done`：已交付；完成后移入发布记录，不长期留在路线图。

跨模块、接口变化或重要产品取舍必须先创建 RFC。候选项未进入 `planned` 前，不得把预留字段或 action 写进 [`api.md`](api.md)。

## 质量与运行基础

| 候选项 | 状态 | 进入 planned 前必须确认 |
| --- | --- | --- |
| 目标云环境集成验证 | `candidate` | 覆盖真实云函数、数据库权限、集合初始化、临时头像和清理链路 |
| 微信开发者工具冒烟矩阵 | `candidate` | 普通 5 人局、单人 5 人局、分享加入、切后台恢复和终局 |
| 云资源用量观测 | `candidate` | 按函数/action/数据库读写拆分基线，定义每玩家小时和每局预算 |
| API/文档漂移检查 | `candidate` | 自动比对 action、内部链接、术语和历史文档状态 |
| 前端关键流程自动化 | `candidate` | 明确微信运行环境可用工具及适合自动化的流程边界 |

## 架构优化候选

| 候选项 | 状态 | 约束 |
| --- | --- | --- |
| 差异化私密快照更新 | `done` | 已通过内存中新旧投影比较减少无变化席位写入；保持投影一致性 |
| 更细粒度在线状态 | `candidate` | 心跳不能重新绑定高频快照读取；离线状态不参与规则裁决 |
| 契约类型或 Schema | `candidate` | 以当前 JS API 为输入，不能先设计一套与实现脱节的类型体系 |
